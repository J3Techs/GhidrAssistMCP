## BSim and headless shutdown corrections

**2.3-retry is a lifecycle/observability improvement, not proof of a permanently unrecoverable singleton.** [BsimRuntime:122](../src/main/java/ghidrassistmcp/bsim/BsimRuntime.java#L122) intentionally retains ownership when its worker does not terminate. A later retry after worker exit can finish journal updates and clear the singleton. The worker itself also records failure/cancellation at [line 90](../src/main/java/ghidrassistmcp/bsim/BsimRuntime.java#L90).

Prepare explicit stopping/terminated state and idempotent finalization. Preserve retry. Never clear the singleton or release program/project consumers while its worker is alive. Do not create a second runtime to bypass the stopped instance. Finalize queued journals after termination, without overwriting legitimate terminal worker records.

**2.11 remains a confirmed omission:** [the no-project backend shutdown](../src/main/java/ghidrassistmcp/GhidrAssistMCPHeadlessServer.java#L212) drains generic tasks but does not coordinate BSim. Any repair must account for the process-wide singleton so stopping one backend cannot accidentally terminate another backend's work.

Headless shutdown failure can leave `running=true` after HTTP has stopped. The status/restart path must distinguish listener state from worker termination. Also verify the external `analyzeHeadless` ownership boundary: throwing from [the launcher's finally block](../src/main/java/ghidrassistmcp/scripts/GAMCPStartServerScript.java#L90) alone does not establish that the caller will keep its project open.

Acceptance tests: blocked fake worker; timeout retains singleton/consumers; no new runner admitted; worker exits; retry/finalizer closes exactly once; terminal journals remain coherent; both backend variants behave consistently; launcher ownership survives the relevant failure boundary. Avoid real sleeps of 20 seconds by injecting bounded shutdown waits in fixtures.
